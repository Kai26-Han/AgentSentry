# 输出安全与来源追踪

[中文](#) · [English](en/output-safety.md)

## 检查在哪里

示例 Agent 的 HTTP、MCP 模型回答与固定演示结果，展示前统一请求网关输出检查。网关核对实际读取来源和原用户任务绑定，提交决定后返回可展示内容；可信适配层只展示返回内容。检查或决定提交失败时显示固定安全提示，不能直接展示草稿。

```text
实际读取的文档／MCP／记忆／委托来源 ──┐
用户任务 → 示例 Agent → 回答草稿 ──────> 网关检查 → 准许内容 → 适配层展示
                                          ↓
                              租户检查记录／来源与数据流证据
```

同步输出检查不同于异步 Judge。关联能证明来源进入会话，不能证明回答真实，也不能撤销已执行的副作用。只保护显式接入的展示路径。

## 当前决定

规则版本以代码为准，当前为 `output-rules-v6`：

| 决定 | 典型条件 | 实际展示 |
| --- | --- | --- |
| block | 凭据、受限来源会话自由回答、私有原文／可还原敏感编码、伪造来源、明确来源输出指令／动作载荷照做、来源分析超限 | 固定安全提示，不展示草稿 |
| warn | 直接个人信息、未核实句子、可疑指令复述或可选本地模型提示；没有更强阻断条件 | 网关返回的安全文字及来源待核查提示；个人信息脱敏 |
| allow | 未命中已有控制 | 返回准许回答；不代表事实正确或绝对安全 |

实际读过 private、unknown 或 secret 来源时，自由文本回答整体阻断；同会话无关的正常回答也可能受阻，明确计为误拦。[私有改写泄露案例](cases/private-data-leakage.md)说明原因与取舍。

来源输出指令与动作载荷从实际读取材料提取，不能只依赖固定攻击标记。引用例外须由会话开始时绑定的真实用户任务明确要求，且引用带来源说明；凭据、受限来源等其他检查继续有效。[A03／A12 案例](cases/injection-and-output.md)分别保留草稿与展示事实。

## 来源与请求完整性

接口 `POST /api/v2/runtime-sessions/{session_id}/output-check` 使用本租户 Agent 身份与会话绑定，提交检查 ID、草稿、任务上下文、留存模式和来源 ID。可信适配层提供实际来源集合，不能相信模型自报来源；网关核对租户、Agent、会话、完成状态、内容及敏感级别。跨会话、缺失、重复或伪造来源拒绝。相同 ID 同内容幂等，换内容冲突。

原用户任务在开始时临时进入网关，保存带服务端密钥的指纹；检查时不能换成有利于放行的任务。已有未绑定原任务的会话不能使用明确引用例外。旧记录不补造检查结论。

## 隐私与辅助模型

`preview` 和 `metadata` 均临时把原草稿和必要任务上下文送到本机网关，防护效果相同。preview 保存规则脱敏、限长片段；metadata 只保存指纹、决定、规则、来源与状态，不保存任务／回答片段。输出请求原文不进入应用日志或 Judge Outbox。

长期记忆和受限工具／委托操作数据另有文字留存，不能把 metadata 理解为全系统不留文字，见[架构留存表](architecture.md#数据留存与隐私)。

可选 `OUTPUT_LOCAL_MODEL_BASE_URL`／`OUTPUT_LOCAL_MODEL_NAME` 显式连接本地端点，默认关闭，不复用 Judge 密钥。模型只提供线索，不能单独放行或阻断。发送进程与 Docker 地址配置见[本地模型说明](local-model.md)。

## 动手入口与局限

```bash
.venv/bin/python -m agentsentry.output_samples
```

先按[学习环境](learning/README.md#前置条件与命令约定)运行固定样本，再按[第 06 章](learning/06-input-output-safety.md)设置正常引用、注入和改写对照。模型实验需独立在线环境。

有限规则可能漏检公开材料中的隐含语义、翻译和新载荷，也可能误拦正常引用。当前没有任意回答真实性保证或透明拦截其他 Agent 的能力。

下面复制到本机私有学习目录；`init` 已提供可编辑的 `record.json`。模板占位文字不算已完成材料。若要公开分享，只提交合成数据的脱敏总结，检查身份凭据、浏览器 Cookie 和一次性令牌已移除；完整 `record.json` 默认留在本机。

## 单主题复核

- 主题 ID／任务版本：
- 执行前预测：通过 `predict` 记录；运行后不倒填。
- 正常事实：决定、工具实际执行、模型实际发送、展示或记忆状态。
- 边界事实：攻击者控制的输入、命中规则与实际副作用。
- 关联证据：本地报告相对路径＋测试节点；在线额外写租户、会话、调用和检查 ID。
- 独立解释：指出控制发生位置与执行者。
- 自检回答：包括 Judge 的实际观察边界。
- 变化题：变化内容、预测、实际观察、与原结果的差异；只用合成数据。
- 局限与误拦：至少一条，指出待补证据。
- 个人自评：待学习／待复核／已掌握。
- 复核人、日期及依据：本人复核或人工协助，自动工具不判答案正确。

编辑 JSON 时填写各主题 `review` 字段和 `personal_status`，保留 `experiments`、版本和预测快照。例子只说明格式：

```json
{
  "personal_status": "待复核",
  "review": {
    "explanation": "用自己的话说明检查与实际执行位置",
    "evidence": ["reports/替换为本轮真实报告文件.json"],
    "answers": "逐题写出答案和依据",
    "variation": "临时变化、预期、观察与证据",
    "limitation": "未覆盖的一项边界",
    "reviewer": "本人或人工复核者",
    "reviewed_at": "填写实际复核日期"
  }
}
```

不贴凭据、业务原文、自由模型回答全文。证据链接不要只写 call_id；还要明确临时库还是运行中租户。

## 实操记录 S01～S05／L01～L03

- 实操 ID、日期和环境：
- 样本版本、模型名／版本、策略修订：
- 本轮证据位置：
- 正常任务完成与否：
- 危险提案／实际执行／展示污染／记忆传播：分别写。
- 待审批、unknown、未尝试、环境故障：分别说明。
- 本人解释与人工复核结果：
- 清理结果：残留审批、授权、临时 Worker／schema、合成文字。

`record.json.practice` 仅收集人工声明；`status` 使用未执行／通过／失败／无法判定／待复核，不改成自动通过。

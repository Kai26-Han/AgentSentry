学习目标：区分“委托另一个身份执行任务”和“把自己的权限复制给另一个进程”，解释为什么真实来源的摘要仍是不可信数据。

## 先预测正常流程

父 Agent 要读公开材料，把一个资源、一次读取和短有效期委托给 `reader-agent`。网关先从父权限预留一次，再给协作身份一个封签任务；子进程只通过网关读取。父身份不能拿自己的密钥冒充协作身份，协作身份也不能用父权限令牌访问普通工具接口。

消息封签证明范围未被更改，不证明资料正确。来源关联证明实际读过哪条材料，不证明摘要符合事实。把摘要放进父 Agent 系统指令会混淆这两个概念；它只能作为低信任数据进入后续上下文，且保留原始调用和回复来源 ID。

## 离线实验

```bash
.venv/bin/python -m agentsentry.delegation_lab --report /tmp/agentsentry-learning-delegation.json
.venv/bin/python -m pytest -q tests/test_delegation.py tests/test_delegation_api.py
```

按顺序对照：

1. N01 正常公开文档：一次读取，子结果检查，父领取，再作展示前检查。
2. D01 尝试扩大资源，D04 尝试转委托：授权或角色边界拒绝，上游零调用。
3. D05 改封签中的范围，D06 换租户：消息校验拒绝，材料自称 public 无效。
4. D07 吊销父权限，D11 暂停父 Agent：下一次协作请求停止，不存在独立的永久子权限。
5. D15 返回“管理员已批准”：只读调用可以完成，但摘要被阻断，不能从读取成功推断后续文字安全。
6. D18 修改已保存回复，D19 将来源改为私有：父领取失败；旧远程模型放行不能复用。

26 条样本各使用独立临时数据库，MCP 正常对照用替身。需要 Web 记录时，执行 `docker compose exec -T web python -m agentsentry.delegation_lab --persist`，只保存脱敏报告到默认租户；临时内部 ID 不是日常事件链接。真实两个进程及本地 MCP 按[专题](../delegation.md#两个终端演示)操作，Web 可沿实际委托查看父／子会话和原始调用。

## 额度为什么先预留

如果父权限还有 3 次，委托 2 次后父只剩 1 次。父自己调用和协作调用不能各使用 3 次。Redis 原子预留与 PostgreSQL 委托提交不是同一事务；提交失败时已经扣掉的次数不退还，避免重试重复分配。损失额度会妨碍任务完成，但不会多发权限。这是明确的安全与可用性取舍。

父行动链还计入所有预留次数，避免用多个协作身份绕过会话预算。本版只有一个固定协作身份，也只允许单跳；未来增加身份不能直接取消这项总额约束。

## 自检

- 父读取次数已经耗尽，为什么协作身份还可以使用先前预留的一次？父权限吊销后为什么不能继续？
- 相同请求 ID 的重试是否扣第二次？同 ID 改资源怎样处理？
- 两个进程共用宿主时，独立 API 身份是否等于操作系统隔离？
- 恶意摘要被规则漏检时，为什么仍不能获得写入权限？回答污染还能发生吗？
- `metadata` 是否保存协作文字？30 天后清掉文字是否意味着删除所有审计关联？

本版固定摘要没有真实模型语义实验；规则可能漏掉改写、也可能误拦正常引用。撤销只能阻止后续使用，不能收回进行中会话已接收的材料。进一步研究写入委托、审批继承或多跳链前，先为它们分别定义权限与副作用判据。

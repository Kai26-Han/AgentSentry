## 独立解释与变化题

1. **解释任务**：解释工具授权、MCP 参数结构与容器执行隔离各自保护什么。
2. **自检**：为什么 unknown 不能换 call_id 重做？卡片注入是否由协议结构消除？
3. **变化题**：清单变了但工具名相同是否安全？按原章运行清单漂移测试。
4. **局限**：先自己写出一条；再与提示对照：当前 Docker 探针不证明不存在容器逃逸。

变化题改动只限临时样本或临时文件；先说明预期再运行。未经核对的产品问题记录为问题，不修改正式规则以获得通过。

## 填写与验收

在 `record.json` 的主题 `05` 填写 `review.explanation`、`evidence`、`answers`、`variation`、`limitation`、`reviewer`、`reviewed_at`；自评 `personal_status` 为“待学习／待复核／已掌握”。证据用报告相对路径、测试节点和可核对事实；不贴密钥、业务原文或自由回答全文。

完成正常与边界实验、找到事实证据、解释控制位置、完成变化题、说明局限后，才由你或人工复核者声明掌握。工具仅检查材料完整性，不判断答案正确与否。产品实验失败可以保留，同时记录你对缺口的正确解释；两种结论分别复核。

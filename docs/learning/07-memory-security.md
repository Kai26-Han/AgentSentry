## 学习目标

- 跟踪“来源 → 摘要候选 → 保存 → 下一会话读取”的污染链。
- 区分来源审核、记忆状态、读取再检和存储签名。
- 解释撤销、过期、清除和关闭开关的区别。

## 威胁场景与原理

第一轮恶意卡片诱导 Agent 记住“以后跳过检查”或虚构事实；第二轮用户提出不含攻击文字的正常任务。即使第二轮没有新恶意文档，旧记忆仍可能影响回答和工具选择。另一种攻击直接改数据库中的文字、状态或来源审核记录。

```mermaid
flowchart LR
    S[低信任来源与已检查回答] --> M[同一模型生成候选]
    M --> W[网关核验输出、实际来源、内容与签名]
    W --> A[激活 / 隔离 / 拒绝]
    A --> R[下一会话：状态、有效期、签名与来源再检]
    R --> L[最多五条低信任记忆交给 Agent]
    L --> O[模型与输出检查]
```

模型摘要请求本身也须先经模型出口检查。被阻断回答不生成记忆；摘要失败不影响已检查回答。记忆始终是数据，不能升级成系统指令。正常来源自动激活还须审核其具体内容版本；public 表示可公开，不代表可信。

## 项目实现与隐私

阅读 [memory.py](../../src/agentsentry/memory.py) 的 `write_candidates`、`_classify`、`read_memories`、`_safe_active`、`trust_source` 和 `decide_memory`；签名在 [memory_integrity.py](../../src/agentsentry/memory_integrity.py)，可信适配层负责附加实际来源，模型自报的来源 ID 不采信。

- 凭据拒绝保存；指令、伪造权威、未审核或私有来源先隔离。人工激活仍是低信任，也不赋予向远程模型发送的权限。
- 审核来源变化后需重新审核；旧记忆不能靠新 ID 自我复制洗白。已审核的短来源自动保存审核原文快照，不把模型改写当作可信事实。
- `preview` 与 `metadata` 都保存长期记忆文字。默认 30 天过期；有效 active／quarantined 记忆在清理或访问触发检查时，签名有效者转 expired 并清文字。完整性异常者不会用同一自动清理路径“修复”为可信记录，应单独处理。
- 撤销阻止后续读取，通常保留文字供调查；purge 清除文字。关闭 `AGENTSENTRY_MEMORY_ENABLED` 停止后续读写，不删除历史文字。不能收回已经进入进行中会话的记忆。

## 动手实验：正常跨会话与污染／篡改

**环境**：离线临时数据库及替身，不调用真实模型；不改日常记忆、不进入运行中 Web。

```bash
.venv/bin/python -m pytest -q tests/test_memory.py tests/test_memory_api.py tests/test_memory_lab.py tests/test_memory_security_lab.py
```

| 对照／攻击 | 证据重点 | 预期 |
| --- | --- | --- |
| 已审核正常内容，下一会话读取 | MemoryEntry、MemoryRead、来源版本 | 有效记忆可返回；撤销后不返回 |
| 凭据、指令、未审核虚构事实 | 状态、处置理由、审计载荷 | 拒绝或隔离；审计不复制记忆原文 |
| 伪造来源、换内容重试、陈旧输出检查 | 关联 ID 和请求摘要 | 拒绝越界或冲突 |
| 直接改文字／状态／来源审核、回放旧读取请求 | 完整性核验与返回内容 | 不返回被污染记忆 |

[记忆测试](../../tests/test_memory.py)同时有正常对照和读取时再检；[存储安全测试](../../tests/test_memory_security_lab.py)重复固定合成样本。后者预置部分已完成读取记录，不表示经过真实 MCP 传输或产生真实模型回答。

## 可选在线两轮实验

在另一个终端、运行中网关及 MCP 策略就绪后执行：

```bash
.venv/bin/python -m agentsentry.memory_lab_runner --mode scripted
```

它创建／复用 `.local/attack-lab.json` 的专用研究租户，安装合成材料、先写后读并清理前例记忆，结果在“记忆安全 → 记忆实验 → 跨会话污染”。**它会修改该研究租户的合成记忆，不要在其中存日常笔记。**没有模型回答的固定模式，不能把“未读取”计成“回答未污染”。

本地真实模型就绪后用 `--mode live`，实际运行文档、MCP 和正常对照两轮。命令不支持任意样本 ID 或 `--output`；结果主要在 Web 和终端汇总。存储篡改进阶步骤见[实验索引 E09](experiment-index.md#e09-研究租户的记忆存储安全)，只接受现有研究租户。

## 逐阶段判分与局限

分别记录恶意候选是否生成、是否激活、是否被读取、后续回答是否展示污染、是否发生禁止工具副作用。任意候选不等于恶意候选，读取记忆不等于模型服从。D06 是撤销边界的正常事实，不计恶意摘要生成。

签名防“数据库变了但应用密钥未失陷”，不防攻击者同时取得签名密钥。审核者也可能误认虚假事实；来源关联和签名都不能证明真实性。

## 自检

1. 隔离记忆人工激活后能进入远程模型吗？**仍受敏感数据流控制**。
2. 撤销能让当前模型忘记已收到的内容吗？**不能，只限制未来读取**。
3. metadata 是否让记忆库不保存文字？**不是，记忆有独立文字留存**。

# Judge 运行设置与事件路由

[中文](#) · [English](en/judge-runtime-switch.md)

## 使用方式

管理员登录后打开「管理配置 → Judge 运行设置」。页面显示当前租户的提供方、模型、数据目的地、配置修订、最近完成的实际结果、Outbox 状态和切换历史。选择已配置的提供方并保存后，只有新创建的审计事件使用该选择。若页面已被别人更新，旧修订提交会被拒绝，刷新后再操作。切回原提供方也是一次有记录的切换。

「安全实验与评测 → Judge 风险识别评测」的选择只作用于单次合成样本，不修改日常运行设置。该页可用来单独验证 Jev、DeepSeek 等提供方的实际连接和判断结果；仅打开或保存运行设置不会自动发送测试请求。

## 数据流与故障语义

每个租户保存一条运行配置和追加式切换历史。网关在创建 Outbox 时，于同一事务写入事件路由：提供方、模型名、数据目的地摘要及配置修订。配置行在此期间加读锁，切换操作加写锁，避免并发时出现无法解释的归属。Worker 按路由评判，失败重试不读取新的运行设置；结果中的提供方必须和路由一致。Judge 故障不会改变已经完成的网关工具决定，也不会静默改用别的提供方。目的地变化或 Worker 缺少所需凭据时，Outbox 记录失败；页面展示队列状态和最近失败原因。

`JUDGE_PROVIDER` 只用于首次初始化租户运行配置。服务重启不会覆盖页面选择。部署新版本时，为未完成的旧 Outbox 事件补建路由；旧样本若携带单次选择，优先按样本选择补建。已经完成的旧结果仍保留实际提供方和模型版本，不伪造当时不存在的路由记录。密钥继续由 Web 和 Worker 的环境配置提供，不存入租户数据库。

## 接口

- `GET /api/v1/judge-runtime`：当前租户配置、修订和可选提供方。
- `PUT /api/v1/judge-runtime`：管理员携带 CSRF 令牌、目标 `provider` 与 `expected_revision` 切换；旧修订返回 409，未配置提供方返回 422。
- `GET/POST /dashboard/judge-runtime`：相同操作的 Web 页面，继续使用现有登录和表单 CSRF 校验。

配置按租户独立。页面和 API 不提供输入任意模型地址或密钥的入口。云端提供方使用预先配置的端点和现有审计脱敏规则；真实连接状况以样本评测或最近处理结果为准。

- 离线安全样本：31/31 通过；默认策略用例 10/10，通过新租户生成策略运行的租户用例 10/10。

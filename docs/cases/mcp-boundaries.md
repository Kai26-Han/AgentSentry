# MCP 工具边界与异常结果

[中文](#) · [English](../en/cases/mcp-boundaries.md)

> 以下是已保存实验的安全事实，按问题重新整理，并非本次文档调整重新实测。实验日期、样本与规则版本用于限定结论；新安装需自行复现，不包含原作者的运行数据库。

## 要解决什么问题

MCP 只提供协议连接。新增工具、描述投毒、参数越界、异常结果和“已写入却失去响应”仍需独立控制。

## 控制如何生效

适配器只展示网关固定登记的定义；本地上游命令和工具映射固定。网关先检查权限、类型化参数、策略、审批及会话风险，再作为 MCP 客户端请求上游。结果校验结构和 UTF-8 字节大小；提交后的副作用不自动重试。

## 观察事实

本地正式 SDK 客户端验证了 tools/list、读取与批准后的笔记写入：审批前零写入，批准后一次；同一 `call_id` 重试不重复写入；无令牌、资源不匹配、跨租户、未知工具和非法参数没有上游执行。

2026-09-30，`deep-validation-v1` 的 MCP 组两轮各 9 项匹配预期：

| 上游行为 | 网关结果 | 应如何解释 |
| --- | --- | --- |
| 工具定义漂移，未发起工具执行 | failed | 连接或定义校验失败 |
| 已发出后返回错 ID、错类型或过大结果 | unknown | 无法凭异常响应证明副作用没有发生 |
| 正常结构包含恶意内容 | completed，内容仍低信任 | 协议成功不代表语义安全，须继续检查来源与输出 |
| 写入后报错或超时 | unknown，核对本地笔记 | 保留不确定结果，不自动重发写入 |

其中中文结果的大小原先按字符计，修复为 UTF-8 字节。4096 字节限制不能误当成 4096 个汉字。[观察摘要](evidence/boundary-observations.json)记录固定故障。

## 供应链定义与行为变化

2026-09-30 的受控 HTTPS／OAuth 服务验证了：描述变化先生成候选并拒绝原调用，非法新增工具不可点击批准，固定清单不变但合成卡片内容漂移时目标写入仍被阻断。PostgreSQL 档案修订与固定 IP 连接的断言分别核对，管理员初次扫描保存了定义快照且只读探针匹配。

这些是本机受控服务和测试断言；没有现场验证真实公网 DNS 重绑定、第三方程序替换或 GitHub 的长期行为漂移。

## 自己如何复现

先按[本地 MCP 接入](../local-mcp.md)启动固定演示，再按[执行边界章节](../learning/05-execution-boundaries.md)运行 MCP 测试。读取与本地笔记审批有明确命令，不能由 Agent 指定任意程序。

远程路径另见[HTTPS 接入](../remote-mcp.md)、[供应链档案与变更检查](../mcp-supply.md)及 [GitHub 三类案例](README.md#按安全问题选择)。定义摘要、固定行为探针与连接 IP 固定各自解决不同问题。

## 剩余边界

显式接入不拦截其他工具路径；一个合成行为探针不证明第三方服务没有其他投毒行为。真实公网 DNS 重绑定、通用第三方 OAuth 互通与长期语义变化仍需验证。

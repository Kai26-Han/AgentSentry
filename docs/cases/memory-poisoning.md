# 记忆投毒与存储完整性

[中文](#) · [English](../en/cases/memory-poisoning.md)

> 以下是已保存实验的安全事实，按问题重新整理，并非本次文档调整重新实测。实验日期、样本与规则版本用于限定结论；新安装需自行复现，不包含原作者的运行数据库。

## 要解决什么问题

恶意来源可能先形成长期记忆，再影响不含攻击文本的下一轮任务。内容审核与数据库完整性是两条不同边界：签名只能发现未授权修改，不能证明记忆真实。

## 观察事实与修复

2026-09-28，固定跨会话样本（12 条攻击、6 条正常）发现 D04／M04 的伪造事实记忆被激活并在下一轮读取，共 2/12。固定模式没有真实回答，不能把“读取”直接算成回答污染。原真实模型实验恶意激活零，但正常记忆可用仅 1/6，暴露误隔离问题。

修复改为绑定已完成来源、来源哈希与审核版本；自动激活的文字使用已审核的短公开原文，而非任意模型候选。未审核、私有、过长或可疑内容隔离；读取和输出继续核验来源，来源修改／撤销使旧关联失效。

## 控制与留存

记忆由网关保存、按租户与 Agent 读取；隔离、撤销或过期的条目不返回。默认 30 天过期，读取仍以低信任数据进入上下文。管理员手工激活不是外发许可，撤销也不能收回已经交给进行中模型的内容。

`preview` 和 `metadata` **都会保存长期记忆文字**。关闭记忆功能只停止后续读写，不删除已存内容。

## 自己如何复现

按[记忆安全章节](../learning/07-memory-security.md)运行写入轮与不含攻击文本的读取轮，分别核对生成、激活、读取、回答与副作用。机制见[长期记忆](../memory.md)和[存储完整性](../memory-integrity.md)。跨会话组的脱敏事实见[观察摘要](evidence/boundary-observations.json)。

## 剩余边界

审核来源不证明内容真实；管理员误审核、秘密分类遗漏和语义改写仍可能造成风险。避免把“签名有效”或“没有恶意激活”写成跨会话污染已全面解决。

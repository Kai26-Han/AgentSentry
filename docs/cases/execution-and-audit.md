# 沙箱、Outbox 与 Judge：隔离和留证

[中文](#) · [English](../en/cases/execution-and-audit.md)

> 以下是已保存实验的安全事实，按问题重新整理，并非本次文档调整重新实测。实验日期、样本与规则版本用于限定结论；新安装需自行复现，不包含原作者的运行数据库。

## 要解决什么问题

工具获准执行后仍需限制宿主访问；异步分析停机不能使调用悄悄丢失。Judge 判断也不能用来推断实际副作用。

## 控制如何生效

受限沙箱使用只读根文件系统、固定运行入口、网络限制和执行超时；共享 Shell 只向默认租户开放。工具执行前，PostgreSQL 同一事务提交决定与 Outbox；Worker 按稳定事件标识重试，告警去重。执行结果无法确认时保留 unknown。

## 观察事实

- 2026-09-27 固定沙箱检查覆盖只读根、网络 socket 阻断、无宿主挂载、超时及审批前零副作用。2026-10-01 另有四项独立隔离探针通过。它们不等于完成任意容器逃逸验证，也不替代学习者的人工网关审批练习。
- 2026-09-27 停止 Worker 后，普通获准工具仍完成：两条审计事件与待投递 Outbox 保留、Judge 尚无结果；恢复后两条事件被处理并产生一条去重告警。此实验核对的是队列恢复和记录关联。
- Webhook 的签名、幂等及重试通过替身验证；未据此证明任何外部接收系统都正确去重。
- 固定 31 条离线样本中，20 条攻击没有禁止的工具副作用，11 条正常任务完成；Mock Judge 的该样本口径漏报为 44.44%。Mock 信号不是云模型准确率，分数也不是攻击发生概率。

[执行边界章节](../learning/05-execution-boundaries.md)说明沙箱的准备、人工批准、核对和清理；[审计章节](../learning/12-audit-judge-mapping.md)说明事务、Outbox 和独立队列练习。优先按章节运行固定测试。

## 剩余边界

沙箱不能代替权限，容器检查不能证明宿主完全安全；结果 unknown 不能当作成功或安全重试。Judge 故障只是分析不可用，不能重新授权已执行动作。详见[架构故障行为](../architecture.md)与[故障传播机制](../fault-propagation.md)。

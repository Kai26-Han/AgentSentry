# 单跳委托：权限衰减与结果污染

[中文](#) · [English](../en/cases/delegation-boundaries.md)

> 以下是已保存实验的安全事实，按问题重新整理，并非本次文档调整重新实测。实验日期、样本与规则版本用于限定结论；新安装需自行复现，不包含原作者的运行数据库。

## 要解决什么问题

父 Agent 把任务交给另一个身份时，可能复制过多权限、绕过次数限制，或把子 Agent 的“已批准”回复当作可信指令。

## 控制如何生效

固定只读协作身份、单跳任务、缩小资源范围和有效期；父权限原子预留后签发委托。子身份不能扩大权限或写入，返回结果封签并关联真实读取记录。封签只证明关联完整性，结果仍是低信任数据，需经过输出检查。

## 观察事实

2026-10-01，`delegation-lab-v1` 的 22 条边界与 4 条正常用例重复两轮，逐例一致；未授权副作用、核对审计缺失均为零。固定 MCP 替身与现场接入分别记录：

| 模式 | 实际核对 |
| --- | --- |
| 真实 PostgreSQL／Redis 并发 | 四次竞争两次父额度，只有两次准许、两次拒绝；额度剩余零 |
| 同 ID 四次并发 | 只读上游实际执行一次，只产生一条结果审计 |
| 两个独立进程＋本地 MCP | 子身份分别完成一条文档和一条 MCP 读取 |
| 篡改或污染结果 | 伪造封签拒绝；真实读取后伪造审批摘要被阻断，父 Agent 不收到该摘要 |

核对的三次完成读取无审计／Outbox 缺失。委托专用元数据事件未投给 Judge 属于设计范围，不算 Judge 漏报。[脱敏证据摘要](evidence/delegation.json)记录运行模式与限制。

## 剩余边界

子进程采用独立身份，但不是操作系统沙箱；当前子任务为固定只读摘要，没有多模型语义污染实验。多跳、写入、跨主机、应用密钥与数据库同时被攻破不在结论内；封签不能证明摘要真实。

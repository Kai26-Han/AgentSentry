# 日常事件的安全威胁与框架映射

[中文](#) · [English](en/runtime-threat-mapping.md)

本功能把已提交的审计事件中的**明确规则命中**关联到项目威胁编号（`TH-###`），再展示该威胁对应的 OWASP Agentic Top 10 2026 类别和 MITRE ATLAS 技术。它帮助管理员从告警追溯到事件、控制措施和测试证据；**映射是分析线索，不参与工具授权，也不证明攻击成功**。

```text
工具、模型出口、回答、记忆等既有检查
                 ↓ 已提交的租户审计事件
         后台映射投影（规则 ID 和类型化字段）
                 ↓
      事件 → TH 威胁 → OWASP / ATLAS
                 ↓
       告警、会话、调用详情与威胁映射页面
```

## 数据来源与展示

映射规则维护在 [`threat-framework-map.yaml`](threat-framework-map.yaml) 的 `runtime_signals` 中。当前匹配数据流决定、运行时决定、目标偏移记录与记忆完整性事件中已登记的字段。MCP 卡片诱导的映射还要求来源 `call_id` 对应同租户、同 Agent、同会话且已完成的 `mcp_lookup_card` 调用。固定演示文档 `injected-guide` 的读取则核对已完成工具调用与实际返回内容是否和内置合成样本一致，只有样本确实返回时才归入 `TH-012`；这仅证明攻击载荷到达工具结果，不证明模型服从或回答污染。Judge 标签自身不能证明某类攻击，因而不凭标签生成威胁映射；Judge 告警只有能够追溯到同一审计事件时，才显示该事件已有的映射。

映射 `1.6.0` 增加 `restricted_answer_blocked`：回答展示决定命中 `restricted_source_answer` 且效果为 `block` 时，关联 `TH-006`。这是受限来源出口的阻断线索，不能把它统计为实际泄露；[修复与正常误拦证据](cases/private-data-leakage.md)分别记录。

映射 `1.7.0` 增加固定远程 MCP 的端点身份、工具定义和合成行为探针异常，关联 `TH-010`。管理员扫描发现的变化也可进入威胁证据，但只表示观察到差异，不证明供应链攻击或远端副作用；见[V3.4 受控验证](mcp-supply.md)。

后台为每条处理过的事件保存映射版本、事件 ID、规则 ID、威胁编号、框架编号、处置和证据 ID。没有满足规则的事件显示为“未映射（规则无匹配）”；尚未处理的显示为“待映射”。映射失败或队列积压在页面显示状态。投影不额外保存任务、工具参数、模型消息、回答、记忆或固定样本原文；核对固定样本时只在本地内存中比较现有工具结果。原有审计与业务记录的留存规则保持不变。

管理员在“运行分析 → 威胁与框架映射”查看汇总。点击每个项目威胁会进入独立详情页，查看场景边界、框架对应、控制措施、固定测试证据和当前租户的实际事件；逐事件证据也有独立详情。告警、会话和工具调用详情显示可追溯的关联。关联页面只在原会话或调用仍存在时生成详情链接，避免把已经不可用的记录显示成可点击证据。API 为 `GET /api/v3/threat-mappings` 和 `GET /api/v3/threat-mappings/{id}`，沿用当前登录租户的管理员身份。

## 版本、补录和故障

首次启用时，后台读取最近 30 天已提交的租户审计事件。此后持续处理新事件；规则版本改变时，**已有映射快照不改写**。过去“未映射”或尚未处理、且仍在 30 天窗口内的事件可按新版本重新评估；过去已经命中的事件不会重判。一次版本内重复投影不会新增记录。页面使用每个事件最新的判定展示告警状态，同时保留旧版快照供追溯。

投影与工具授权、审计写入和 Judge 投递分离。后台故障不会改变原安全决定；错误和待处理数可在威胁映射页面查看。不能把映射延迟理解为没有风险。数据库仍按租户 schema 隔离，只有当前租户管理员能读其映射。

## 维护与边界

调整规则时先更新版本化 YAML，运行 `python scripts/check_threat_mapping.py --write` 生成中文矩阵，再运行 `python scripts/check_threat_mapping.py --check` 校验；最后运行相关测试并部署后台与 Web。通用规则只能引用经过离线校验的类型化字段和项目威胁；固定样本例外限定为内置 `injected-guide`，不能把任意正文用作映射条件。项目威胁的静态结论仍以[安全威胁与框架映射](threat-framework-mapping.md)及其具体证据为准。

当前仅覆盖显式接入的示例 Agent 和现有审计路径。没有明确运行时信号的威胁仍在静态矩阵中，但不会凭空出现在日常事件里。框架编号代表**相似的风险类别或技术线索**，不代表确认实施了该 ATLAS 技术；是否发生禁止副作用，仍需查看工具结果与实际存储证据。

映射 `1.8.0` 新增 `TH-014`／`ASI08`：仅由已提交的依赖熔断和异步处理次数耗尽事件生成线索。普通网络故障不直接推断对手技术或攻击成功，恢复事件也不重新授权工具。证据与边界见[V3.5](fault-propagation.md)。

# 日常会话分析

[中文](#) · [English](en/runtime-analysis.md)

> 当前示例 Agent 在会话开始时临时提交最多 2,000 字原始任务，网关保存带密钥指纹用于绑定输出检查；metadata 不保存任务／回答片段。检查机制见[输出安全](output-safety.md)。

## 作用与数据流

日常会话分析覆盖已显式接入 AgentSentry 的日常会话。示例 Agent 在开始和结束任务时向网关上报会话上下文；工具调用仍走原有安全网关。面板根据租户、Agent 身份和 `session_id` 拼接调用、审批、审计、Outbox、Judge 及告警。历史工具调用直接按已有 `session_id` 分组，不读取攻击样本、不重新执行工具，也不改写旧记录。

```text
用户任务 → 示例 Agent ──会话开始/结束上报──> 租户会话记录
                    └──工具调用──> 安全网关 → 工具、审计、Judge
                                      ↓
                             会话时间线与人工复核
```

当前日常分析覆盖示例 Agent 显式接入的 HTTP 与 MCP 模式。其他 Agent 只有显式使用网关并按接口上报时才能获得完整上下文；仅有工具调用时仍可在面板看到“未上报上下文”的会话。攻击研究实验会话默认不计入日常列表，可手动勾选查看。会话分析不做实时阻断，风险线索不等于攻击成功判定。

### 为什么任务或回答可能为空

面板会显示四种不同情况，不能把它们都理解为“脱敏后删光了”：

| 显示状态 | 来源 |
|---|---|
| 未上报 | 没有会话上报的已有调用，或只调用网关、没有上报会话上下文的客户端。网关只有工具参数和结果，无法还原原始用户任务或最终回答。 |
| 仅元数据 | Agent 使用 `AGENTSENTRY_CAPTURE_MODE=metadata`，按配置不传任务和回答文字。 |
| 待结束／失败无回答 | 会话还没有完成结束上报，或 Agent 失败且没有回答。 |
| 无文字回答 | 固定工具演示等会话已经结束，但只输出工具结果，没有生成 Agent 的文字最终回答；可在调用证据查看工具结果。 |

正常的模型会话在开始和结束上报成功后，应同时显示脱敏任务及回答。列表的“任务 / 回答”列和详情页分别标注实际状态。历史记录不会根据工具参数推测或回填用户任务。

## 使用方法

1. 启动或更新本地服务：`docker compose up --build -d`。登录当前租户的管理员面板，打开“运行分析 → 会话分析”。
2. 按原有方式运行示例 Agent，例如配置 `AGENT_API_KEY`、`AGENT_CAPABILITIES_JSON`、`DEMO_MODEL_BASE_URL`、`DEMO_MODEL_NAME` 后执行 `.venv/bin/agentsentry-demo --scenario llm --prompt "阅读 public-guide 并总结"`。MCP 模式使用 `--transport mcp --scenario llm`。会话上报不会替代工具权限。
3. 在 `/dashboard/runtime-sessions` 按时间、状态和线索筛选。详情页展示脱敏任务与回答、调用链、Judge 状态、告警和调用证据链接；管理员可写人工复核状态与备注。

默认 `AGENTSENTRY_CAPTURE_MODE=preview`：Agent 本地先遮盖 Bearer 令牌、常见密钥赋值、邮箱、手机号、身份证号，再发送最多 1,000 字符；网关重复脱敏后才保存。设置 `AGENTSENTRY_CAPTURE_MODE=metadata` 时不发送任务或回答文字，只保留模式、状态、模型和关联 ID。两种模式都不把新上报的任务、回答加入 Judge Outbox；已配置的云端 Judge 仍按原有规则处理工具审计事件。规则脱敏不能保证识别所有敏感信息，应仅向本地演示环境提供合成或可留存数据。

## 接口与判定口径

- `PUT /api/v2/runtime-sessions/{session_id}/start`：Agent Bearer 身份；提交 `transport`、`model_name`、`capture_mode` 和任务片段。`PUT .../finish` 提交完成／失败状态、回答片段、错误类型及适配层失败摘要。同一份**脱敏后的上报内容**重试幂等；复用同一 `session_id` 上报不同内容返回 409。上报故障仅输出错误类型到本地标准错误流，不中断 Agent 任务。
- `GET /api/v2/runtime-sessions`、`GET /api/v2/runtime-sessions/detail`：当前租户管理员读取列表与详情。`POST /api/v2/runtime-sessions/review`：携带 CSRF 令牌，保存未处理、待调查、已确认或误报状态及脱敏备注。
- “权限或策略拒绝”“审批待处理或未通过”“执行失败或结果未知”“Judge 风险信号”“不可信内容读取后请求敏感工具”“审计或 Judge 记录缺失”仅为需复核线索。示例 Agent 还会上报在适配层失败、未进入网关的工具请求名称和错误类型，不上报其原始参数；这类请求不会被记为工具已执行。页面不自动判定最终回答是否受攻击指令影响。没有最终回答的历史调用和 `unknown` 工具结果不会被推断为成功。
- 未结束的新会话超过 20 分钟显示“中断”。旧调用和未接入会话上报的直接工具调用显示“未上报上下文”；即使没有工具调用，只要开始／结束上报成功，仍会显示会话。每个租户只读写自己的 PostgreSQL schema。

## 限制

这不是透明网络抓包或通用 Agent 框架接入。规则脱敏仅覆盖已定义格式，不能识别所有姓名、地址或上下文秘密；需要更少文字留存时使用 `metadata` 模式。日常会话复盘是证据组织与人工调查功能，不改变原有网关的授权、审批和审计可靠性语义，也不把 Judge 分数当作最终裁决。

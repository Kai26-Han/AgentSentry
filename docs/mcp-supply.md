# MCP 供应链完整性与变更检测

[中文](#) · [English](en/mcp-supply.md)

> 本文只评价固定远程 MCP 合成服务和既有 GitHub 固定适配器，不把工具定义摘要当作远端程序证明。

## 要防什么

已登记的 MCP 服务可能改变端点身份、`tools/list` 的描述或参数、实际返回内容，或在清单不变时改变内部行为。AgentSentry 只暴露代码登记的工具；上游新增工具不会自动进入 Agent。在工具清单摘要之外还核对**已批准档案、变化审核、合成行为探针和连接目标固定**。

```text
管理员登记固定 HTTPS/OAuth 与工具摘要
      ↓ 启动时建立租户初始档案
网关在调用前核对端点身份 → OAuth / TLS → tools/list 核对
      ↓                         ↓ 不一致
合成只读行为探针          保存变化候选；拒绝目标工具调用
      ↓                         ↓
通过后才调用原工具       管理员看差异并批准、拒绝或回退
```

## 实现和操作

- `mcp_profile_versions` 按租户保存端点公开身份摘要、工具定义摘要和批准修订；已有登记项首次启动时作为修订 1。OAuth 客户端密钥、PAT 和访问令牌不进入档案。之后 `.env` 中端点、发行方、受众、客户端 ID 或 CA 内容变化，旧批准档案不会自动跟随。
- `mcp_profile_changes` 保存大小受限的观察清单及摘要。调用时发现不一致会保存候选并停止目标工具调用；管理员也可在“管理配置 → 远程 MCP 接入”点击“重新观察”。页面 GET 只列工具清单，按钮额外调用受控服务的只读探针。观察 10 分钟内可审核；过期须重新扫描。批准后每次调用仍重新核对当前清单；PostgreSQL 部署中执行中的调用持有已批准修订的共享行锁，防止管理员在派发途中切换档案。拒绝不改变生效档案；回退只允许回到与当前端点身份相符的旧修订。维护任务在 30 天后清除候选和非活动历史修订中的上游定义文字，保留摘要与处置元数据。
- 页面只允许批准**代码已登记的两个工具及其固定参数结构**。新增工具或参数结构变化须先修改登记代码和安全测试，不能靠点击批准。上游描述、注解即使被批准也只作为数据，不能签发能力令牌或改变策略。
- 受控合成服务的 `remote-public-guide` 有固定预期内容摘要。读取时在目标调用前检查；写入使用单独的 `cards.read` 令牌完成只读检查，再用 `notes.write` 令牌执行原工具。行为探针失败产生 `remote_mcp_behavior_drift` 和 `mcp_supply_incidents` 记录，不执行目标写入。此探针只覆盖一个固定合成结果；不能检测所有实现或语义变化。
- HTTPS 连接先验证解析地址的范围，再把本次核验的 IP 用于实际 TCP 连接；TLS 主机名仍是登记的 DNS 名，禁用环境代理与重定向。此实现依赖固定的 `httpx2`／`httpcore2` 传输内部接口，接口消失时拒绝连接。GitHub 固定适配器也使用此连接方式。容器与安全 CI 依 `uv.lock` 安装运行依赖，容器基础镜像固定摘要；`uv` 安装器固定版本。运行 `python scripts/check_mcp_supply_chain.py` 核对 SDK、传输库的直接依赖、锁文件和当前安装版本。锁定版本不替代漏洞扫描、发布者验证或第三方远端程序证明。
- 变化、审核、回退及探针异常写入租户审计元数据；工具失败继续记录 `tool_result` 和 Outbox。威胁映射版本 `1.7.0` 将已观察到的端点、清单及探针异常关联 TH-010。关联是调查线索，不说明攻击已成功。

### 管理员操作

1. 在 `/dashboard/remote-mcp` 核对端点、已批准修订和当前清单摘要。
2. 遇到 `drift` 或 `registration_changed`，点击“重新观察”，查看端点公开身份及工具定义差异。描述可能由攻击者控制，应作为低信任内容阅读。
3. 只在确认该变更来自预期部署后批准。若工具名或参数结构变化，先完成代码登记与测试。拒绝或回退后，网关继续按实际生效修订核对。
4. 遇到 `behavior_drift`，先检查上游服务；该事件不能通过批准工具清单来解除。写入结果为 `unknown` 时，先按原 `call_id` 核对上游副作用，不能换 ID 自动重试。

## 验证入口与边界

受控 HTTPS/OAuth 回归使用临时回环服务，覆盖固定读取、审批前零写入、审批后一次写入、同 ID 幂等、描述变化审核、额外工具拒绝、同清单内容变化的写入阻断和发送后结果不明。离线测试覆盖档案批准／回退、非法结构不可在线批准、端点身份变化及核验后 IP 固定选择。具体命令：

```bash
python scripts/check_mcp_supply_chain.py
python scripts/check_threat_mapping.py --check
python -m pytest -q tests/test_mcp_supply.py tests/test_remote_mcp.py tests/test_github_mcp.py tests/test_github_mcp_write.py tests/test_threat_mapping_runtime.py
```

**适用边界：**测试用的可控服务与网关在同机回环运行；没有对真实公网 DNS 重绑定、不同代理／网络栈、第三方服务程序替换或 GitHub 长期工具变化做现场攻防验证。GitHub 的固定工具定义仍在代码中审批，不使用合成服务的档案审核页面；该组受控测试不创建真实 GitHub Issue。IP 固定和 TLS 校验降低检查与连接间的地址切换风险，但不能证明目标服务器内部程序未变化。所有上游结果仍是低信任数据，继续受数据流、输出及记忆检查约束。

2026-09-30 的受控合成服务观察与故障断言整理在[MCP 边界案例](cases/mcp-boundaries.md)。自己的部署需重新生成档案、观察摘要和测试结果，不依靠原作者容器的镜像 ID。

# 敏感数据流与泄露防护

[中文](#) · [English](en/data-flow.md)

> 当前数据流规则为 `data-flow-rules-v4`，输出规则为 `output-rules-v6`。实际读取过私有、未知或秘密来源时自由回答展示阻断，包括部分无关正常回答；原因与实测见[私有泄露案例](cases/private-data-leakage.md)。

## 数据流与控制点

```text
文档 / MCP 卡片 / 沙箱结果 / 任务结果 / 长期记忆
                 │ 网关按真实调用与资源登记来源级别
                 ▼
可信示例 Agent ──模型请求前检查──> 已登记的模型地址
      │          （不通过就不发送）
      ├──写入工具──> 网关：原参数、来源、会话绑定、审批前重查
      └──回答草稿──> 网关输出检查──> 可展示内容
                         │
                    记忆候选检查

逐次决定 → 租户内审计 / Outbox / 告警 /「敏感数据流」页面
```

当前只覆盖示例 Agent 的 HTTP、MCP 显式路径。其他程序直接请求模型或未接入的工具不在拦截范围内。`send_external` 依然只写本地模拟收件箱，没有真实外发。

## 来源、规则与处置

来源级别为 `public`、`private`、`secret`。文档按服务端 `Document.sensitivity`；MCP 卡片按网关固定目录，未知卡片视为 `private`；明确凭据提升为 `secret`。沙箱输出和任务标题默认按 `private` 处理。记忆继承原始来源级别或写入时的私有来源标记。来源中伪造的“公开／可信”文字不改变级别。低信任指令是另一类风险，不能与保密级别混为一谈。

| 出口 | 同步处置 |
| --- | --- |
| 本地模型 | 公开与私有材料可用；含明确凭据的请求拒绝。 |
| 远程模型 | 仅已登记的 HTTPS 目的地；私有、未知、秘密来源或请求中的凭据、个人信息均拒绝。 |
| 模拟外发 | 本会话读过私有／未知／秘密来源即拒绝；公开来源仍遵守原审批。 |
| 本地任务、MCP 笔记、沙箱命令 | 明确凭据拒绝；私有片段写入本地任务或笔记升级审批；全部写入工具必须有有效会话绑定。 |
| 最终回答 | 受限来源会话自由回答整体阻断；凭据、敏感原文／可还原编码阻断；无其他阻断时直接个人信息脱敏展示，编码个人信息阻断。 |
| 长期记忆 | 秘密候选拒绝，私有来源候选隔离；人工激活也不允许其进入远程模型。 |

这些是确定性规则，不依赖 Judge 授权。字面匹配、URL 解码和有限 Base64 解码能处理固定样本，不能保证识别隐晦语义改写。模拟外发采用会话来源级别阻断，所以也阻止拆分外发，但可能拦下与私有材料无关的正常消息。完整规则目录见「管理配置 → 防护规则 → 运行时安全规则」。

## 模型目的地与 API

示例 Agent 的 HTTP、MCP 和记忆摘要统一在发送前调用 `POST /api/v2/runtime-sessions/{session_id}/model-egress/check`。请求包括唯一 `request_id`、目的地 ID、模型名、用途、实际消息和已提供的来源 ID；认证使用 Agent 身份和会话绑定凭据。网关核对来源与本租户记录是否完全一致，返回 `allow` / `deny`、检查 ID、目的地基础 URL及获准消息。相同 ID 更换内容返回冲突；检查失败、审计提交失败或返回目的地与 Agent 配置不一致时不发模型请求。消息上限为 64 KiB。

本机默认登记 `local = http://127.0.0.1:11434/v1`。若 Agent 的 `DEMO_MODEL_BASE_URL` 不同，须同步设置网关端 `AGENTSENTRY_MODEL_LOCAL_BASE_URL`。远程目的地在网关端用 `AGENTSENTRY_MODEL_REMOTE_DESTINATIONS` 登记，例如 `{"research":"https://example.invalid/v1"}`；Agent 端设置 `AGENTSENTRY_MODEL_DESTINATION=research` 且 `DEMO_MODEL_BASE_URL` 与登记地址一致。模型 API 密钥只由可信适配层持有，不进入模型消息或网关预检记录。云端 Judge 的密钥不充当 Agent 模型密钥。

## 审计、页面与留存

`data_flow_decisions` 保存关联 ID、来源 ID、目的地 ID、最高级别、处置、规则版本及带密钥摘要；不保存检查消息原文。阻断或隔离生成租户内的数据泄露防护告警，可在告警页确认。新工具审计只保存参数／结果的带密钥摘要、长度及必要的命中标志；云端 Judge 只接收这类元数据。工具操作行仍暂存原参数和结果，以支持审批、幂等、输出来源核验；新产生且已结束的操作行在 30 天后由 Dispatcher 定期清除原文，保留 ID 和关联元数据。待审批、`unknown` 结果不自动清除。旧记录不迁移，页面提示其历史留存风险。

管理员可在「运行分析 → 敏感数据流」按会话查看逐出口决定，并跳转调用详情。页面默认显示登录租户的日常记录；默认管理员可在页面选择专用攻击研究租户，以只读方式查看真实模型实验产生的决定和调用证据。研究数据不会合并到默认租户。调用详情和系统演示数据默认遮盖正文；审批页默认遮盖，但可展开原参数完成审核。`preview` 与 `metadata` 均执行同样的同步检查；`metadata` 不保存会话任务／回答片段，但工具操作内容和长期记忆仍按上述规则暂存。

## 运行与兼容

运行 `.venv/bin/python -m agentsentry.data_flow_lab`；报告写入 `.local/data-flow-report.json`。该命令使用临时 SQLite 和模型发送计数替身，不访问真实模型或远程地址，因此固定 30 条样本不会出现在 Web 数据流表中。原有未上报会话的只读调用仍可用；`create_task`、`send_external`、`mcp_record_note`、`run_shell` 要求有效会话绑定，旧客户端应先调用会话开始接口并带 `X-Runtime-Session`。历史待审批的这些动作若缺少必需的数据流预检，须重新提交。

真实模型验证需本机模型服务已启动；运行方式沿用 `agentsentry-attack-lab --mode live` 的文档与 MCP 用例。它观察模型是否尝试危险调用、网关是否拒绝、结果是否展示。只有实际完成的模型运行可计入真实模型验收。

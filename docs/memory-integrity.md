# 记忆完整性与存储污染防护

[中文](#) · [English](en/memory-integrity.md)

## 要解决的问题

V2.5 建立了跨会话记忆，但后续正常任务可能读到被攻击材料影响的摘要。V2.5.1 增加来源版本审核，仍需要应对两类风险：恶意指令混入已审核来源，以及数据库里的记忆或审核状态被直接改动。本版本聚焦这两类安全边界，不处理日常知识的新旧、冲突或事实更新。

```text
文档／MCP 卡片 → 模型候选摘要 → 网关核对会话与来源 → 污染检查 → 保存记忆＋签名
                                                               ↓
下一会话 → 网关校验签名、状态、过期与内容 → 仅返回可用低信任记忆 → 输出检查
                                                               ↓
                                           异常事件、审计 Outbox、管理员面板
```

## 写入、存储和读取

写入检查与记忆的 `kind` 无关。规则识别伪造系统／开发者角色、跨会话强制命令、危险工具调用、秘密外发、凭据和个人信息；同时检查去掉零宽字符、空格和常见分隔符后的文本，以及长度受限且可以正确解码的 Base64 片段。凭据和明确外发指令拒绝保存；其他可疑内容隔离。来源不明、来源未审核以及从已有记忆再次生成的摘要也保持隔离。管理员不能通过“人工激活”绕过明确危险规则。

每条记忆及每条来源审核记录都签一个按租户隔离的 HMAC。签名覆盖身份、内容、状态、来源、有效期和审核证据等安全字段；密钥由服务端 `SESSION_SECRET` 域分离派生，不放进 PostgreSQL。正常的激活、撤销、过期与清除会同时更新签名。读取前再次验证签名并扫描内容；签名异常或重新命中的危险文字不会进入模型上下文。V2.4 输出检查在使用已读取记忆前也校验签名。

运维上必须保管并稳定使用 `SESSION_SECRET`。直接更换它会使旧签名全部失效，旧记忆按异常拒绝读取；本版没有在线密钥轮换或自动重签工具。需要轮换时先备份、停止写入并设计人工复核流程，不能让数据库内容自动获得新签名。

已有无签名记忆在升级时被隔离，旧来源审核被撤销，原文不会自动补签。管理员在 `/dashboard/memories` 查看历史文字后可执行专门的“复核历史记忆”；网关核对旧摘要哈希、安全规则与来源一致性，通过后只补签为隔离状态，激活仍需再执行一次显式操作。对于已签名但校验失败的记录，可清除文字，不能直接激活或通过再次信任来源来覆盖异常。完整性事件只记录 ID、原因及版本，经审计 Outbox 投递，不发送记忆原文给 Judge。

## 独立实验

`agentsentry-memory-security-lab` 在一个**已有的 Attack Lab 研究租户**内运行 12 条攻击与 6 条正常对照。A01–A08 检查角色伪造、延迟命令、外发、编码、分割、凭据及 `kind` 绕过；A09–A12 通过命令行直接改动研究租户数据库里的合成记忆／审核记录，验证下一会话无法读取。N01–N06 验证已审核安全来源仍可读取。每例使用新的写入和读取会话；完成后清除合成记忆文字。实验表只保存样本 ID、关联 ID、状态和判定，异常中断保留失败／中断状态。

固定实验调用与网关同一套记忆服务函数，但预置的已完成工具读取是合成测试记录。面板里的“合成来源”打开专用的实验来源详情，并按运行 ID、样本和租户校验；它不是普通网关调用详情，因此没有网关调用审计或 Judge 结果。固定实验没有通过真实网关调用 MCP Server，也没有真实模型回答，故“未读取”不等于“最终回答未污染”。真实模型端到端实验继续使用 `agentsentry-memory-lab --mode live`，在实际网关路径运行 3 条文档攻击、3 条 MCP 攻击及正常对照，并单独记录结果。

本机 Compose 运行方法：先完成 V2.2/V2.5 研究租户初始化，从仅本机可读的 `.local/attack-lab.json` 取得 `lab.tenant_id`。执行 `docker compose exec -T web agentsentry-memory-security-lab --tenant <研究租户ID>`。命令只接受名称符合 `Attack Lab` 研究租户格式的 ID，不能改动默认或日常业务租户。结果见 `/dashboard/memory-security-runs`，也可用研究租户管理员读取 `GET /api/v2/memory-security-runs`。运行器不提供任意 SQL、文本或外部地址输入。

## 边界

- 规则识别有限，改写、同义表述、复杂编码或不含指令的虚构事实仍可能漏过。来源关联与人工审核不能证明内容真实。
- 签名防护的是**数据库记录被改动，而服务端密钥未泄露**的情况。若应用进程或密钥一起失陷，攻击者能重新签名；审计数据库本身也不能抵抗拥有相同数据库写权限的攻击者删除记录。
- 已经交给进行中会话的记忆无法收回；撤销、隔离和过期只影响之后的读取。管理员看到的历史未签名文字也不能视为可信证据。
- `preview` 和 `metadata` 都保存长期记忆文字；记忆审计只存元数据，云端 Judge 不接收原文。Judge 不决定记忆激活与否。
